# Deterministic 3×3 Sword Combat — Prototype Specification

**Audience**: Gameplay developer with no prior context.

**Purpose**: This document specifies a deterministic, geometry‑driven melee combat system inspired by historical swordplay and cinematic slow‑motion decision moments. It defines data, rules, and algorithms required to implement a playable prototype. UI/UX is intentionally excluded.

---

## 1. High‑level Concept

Combat is built around **guard selection**, **weapon movement vectors**, and a brief **decision pause (bullet‑time)** when attacks become threatening. Players freely adjust guards until one actor initiates a threatening weapon movement. At that moment, time nearly stops, allowing both actors to **commit resources** and **reason about geometry, timing, and intent**.

Outcomes are resolved deterministically using a **Line Dominance Score (LDS)**, which compares how well each actor controls the contested line of attack at the moment of blade contact.

---

## 2. Core Loop

1. **First Pause**
   - Actors may start any action. P1 and P2 select their Actions blindly (they don't see the opponent's choice) and secretly (the opponent doesn't see it).

2. **Threat Initiation**
   - An actor starts a weapon movement (a swing or thrust).
   - If the movement can plausibly reach the opponent, the system enters **INDES**.

3. **INDES (Decision Pause)**
   - Time slows to near‑zero.
   - Both actors may:
     - Commit **AP_pre** (AP committed before resolution).
     - Spend **Focus (FP)** to compress timing.
     - Change guard (costs AP and is visible to the opponent).
     - Declare **intent** for this exchange.

4. **Resolution**
   - Weapon paths are evaluated.
   - If paths intersect, compute LDS for both actors.
   - Compare LDS values and resolve according to intent.

5. **Aftermath**
   - AP and FP are consumed.
   - AP regenerates between exchanges.
   - Focus never regenerates during a fight.

---

## 3. Spatial Model

### 3×3 Guard Grid

Guards are represented by a 3×3 grid indexed as:

```
1 2 3
4 5 6
7 8 9
```

- Each cell represents a weapon position relative to the body.
- The center (5) represents the centerline / forward presence.

### Weapon Movement

A weapon movement is defined by:
- **start**: guard cell (1–9)
- **end**: destination cell (1–9)
- **path**: straight 8‑directional line from start to end (inclusive)

If `start == end`, the movement is treated as a thrust/point.

---

## 4. Resources

### Action Points (AP)
- **Max AP per Exchange (`MaxAP`):** Integer, Equal to: rounddown(Endurance)
- AP regenerates between exchanges.
- AP committed **before INDES** counts fully.
- AP committed **after INDES** counts at **50%** value.

### Focus (FP)
- **Max Focus: (`MaxFP`)** Integer, Equal to: rounddown(Willpower / 5)
- Represents perception, balance, and ability to catch up in time.
- Does **not** regenerate during combat.
- Each FP converts into effective timing power.

---

## 5. Intent

Intent changes **how the LDS difference is interpreted**.

Supported intents:
- **HITTER** — attempt to land a damaging blow.
- **TAKER** — attempt to seize the line and convert to a bind/control.
- **PROVOKER** — attempt to bait an overcommit and punish it.

---

## 6. Contact Detection

1. Compute both weapon paths.
2. Compute the **intersection set** of path cells.
3. If empty → no blade contact.
4. If non‑empty:
   - For each actor, find the **earliest index** in their path that is in the intersection.
   - This index defines **steps_to_contact**.

---

## 7. Line Dominance Score (LDS)

LDS measures control of the contested line at contact.

```
LDS = w_timing   * TimingComponent
    + w_position * PositionComponent
    + w_angle    * AngleComponent
    + w_structure* StructureComponent
```

All components are deterministic and normalized.

---

## 8. LDS Components

### 8.1 TimingComponent

**What it represents**: Who arrives first to the contact point.

**Inputs**:
- AP_pre
- FP_spent
- ActionSpeed
- steps_to_contact

**Computation**:

```
AP_equiv = AP_pre + K_FP * FP_spent

if steps_to_contact == 0:
    reach = AP_equiv * speed * 2.0
else:
    reach = (AP_equiv * speed) / steps_to_contact

TimingComponent = clamp(reach / TIMING_CEILING, 0, 1)
```

**Player meaning**:
- Early commitment wins time.
- Focus is a scarce but powerful way to catch up.

---

### 8.2 PositionComponent

**What it represents**: Guard preparation and distance efficiency.

**Factors**:
- Alignment of starting guard with swing direction.
- Distance traveled before contact.

**Computation**:

```
PositionComponent = alignment_bonus
                  - distance_penalty_coeff * (steps_to_contact / path_length)
```

Clamped to a small range (e.g. −0.25 to +0.25).

**Player meaning**:
- Starting in the right guard makes attacks cheaper and stronger.
- Poor preparation must be compensated with AP or Focus.

---

### 8.3 AngleComponent

**What it represents**: How the two weapon vectors meet.

**Procedure**:
1. Convert both movements into 2D direction vectors.
2. Measure angle φ between them.

**Rules**:
- φ ≥ 135° → **Opposing bind**: both gain a small bonus.
- 60° ≤ φ ≤ 120° → **Crossing**: earlier arriver gains bonus.
- φ ≤ 45° → **Aligned**: slight penalty (pure speed contest).

**Player meaning**:
- Head‑on clashes are gritty and stable.
- Cutting across an opponent’s line is powerful if timed.

---

### 8.4 StructureComponent

**What it represents**: Blade mechanics and follow‑through quality.

**Modifiers** (examples):
- Point/thrust directly at centerline → bonus.
- Long‑edge alignment → bonus.
- Ending in exposed flank → penalty.

Values are summed and lightly weighted.

**Player meaning**:
- Some swings threaten the body more decisively.
- Good structure enables strong follow‑ups.

---

## 9. Resolution via Intent

Let:
```
Δ = LDS_A − LDS_B
```

### HITTER
- Δ ≥ HitThreshold → clean hit.
- Small positive Δ → glancing hit / overextension.
- Δ ≤ GuardThreshold → attacker loses initiative.

### TAKER
- |Δ| ≤ NeutralThreshold → bind achieved.
- Large negative Δ → taker dominates line.
- Large positive Δ → taker fails.

### PROVOKER
- If opponent committed heavily into declared bait line:
  - Apply LDS swing in provoker’s favor.
- If opponent does not bite:
  - Provoker gains no immediate benefit.

---

## 10. Cancelling and Disengage

- Attacks may be cancelled **before INDES lock**.
- Cost is proportional to AP_pre already committed.
- Any Focus spent by the opponent is still lost.

This preserves the idea that forcing reactions has value.

---

## 11. Design Intent

This system:
- Makes **guard choice and weapon direction meaningful**.
- Preserves **player agency** during the slow‑motion decision pause.
- Keeps outcomes deterministic and explainable.
- Allows deep strategy while remaining numerically simple at the surface.

The Line Dominance Score is not shown directly to players, but every decision they make influences it in a readable way through timing, geometry, and structure.

---

## 12. Implementation Priorities

1. Grid + path + intersection logic
2. INDES pause with AP / FP commitment
3. LDS component calculations
4. Intent‑based resolution
5. Debug logging of all intermediate values
